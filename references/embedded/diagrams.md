# Diagrams

Use diagrams to explain structure, not to decorate the paper.

## Good Diagram Types

- Method flowchart
- Algorithm pipeline
- Data processing flow
- Model architecture
- Evaluation framework
- Causal or system relationship diagram

## Boundaries

- Data charts belong to computation and visualization.
- Diagrams explain process, logic, relationships, or architecture.
- Do not create a diagram if a sentence or table is clearer.

## Diagram Quality

- Use concise labels.
- Keep flow direction consistent.
- Avoid crossing lines where possible.
- Make the diagram readable in the final paper size.
- Include captions and references in the paper.

## Deliverables

Store diagram exports under `figures/`. When using a diagram editor, keep source files next to exports when possible.
